# Чеклист код-ревью

## Перед отправкой на ревью

- [ ] Код соответствует гайдлайнам
- [ ] Все тесты проходят
- [ ] Нет закомментированного кода
- [ ] Нет отладочных выводов (console.log, println)
- [ ] Обновлена документация

## Что проверять при ревью

### Логика

- [ ] Решает ли код заявленную задачу
- [ ] Нет ли избыточной сложности
- [ ] Обработаны ли граничные условия
- [ ] Правильно ли обрабатываются ошибки

### Производительность

- [ ] Нет N+1 запросов
- [ ] Нет утечек памяти
- [ ] Асинхронный код не блокируется

### Безопасность

- [ ] Нет хардкода секретов
- [ ] Валидируются входные данные
- [ ] Проверяются права доступа

### Поддерживаемость

- [ ] Понятные имена переменных и функций
- [ ] Достаточно комментариев
- [ ] Код легко тестировать

## Как давать обратную связь

- Будь конкретным: "давай переименуем `x` в `user_count`"
- Объясняй почему: "этот запрос может быть медленным, добавим индекс"
- Отмечай хорошие решения: "круто что вынес это в отдельную функцию"
- Используй `nit:` для незначительных замечаний

## Время ревью

- Отвечай на ревью в течение 24 часов
- Не растягивай ревью больше чем на 3 итерации
